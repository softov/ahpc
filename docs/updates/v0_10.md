# ahpc 0.10

> ## The good stuff
>
> The changes screen does git's work, a refusal says what to do about it, and the tool server answers calls at the same time.
>
> - [Commit and pull requests from the screen](#the-changes-screen): stage, unstage, discard and commit a file or every file, and prepare a pull request in a form.
> - [A refusal says why](#connection-and-tokens): a refused connection token is told apart from a host that is down, and a refused command names the variable that lets it through.
> - [The tool server answers calls at the same time](#the-tool-server): a `ping` or a `confirm_tool_call` is answered while `send_turn` waits, and a cancelled call stops its turn.
> - [A command exits with the host's answer](#commands): a refused action exits 1 with the host's reason.
> - [Usage and tasks](#commands): `session history` prints each turn's tokens, cost and context.

## 0.10.0 - 2026-11-04

### Upgrading

- The repository is [`ahpio/ahpc`](https://github.com/ahpio/ahpc), and the docs are at [ahpio.github.io/ahpc](https://ahpio.github.io/ahpc/). Old links redirect. The npm name stays `@softov/ahpc`.
- `ahpc auth <resource>` takes the resource token from `--resource-token`, `AHPC_TOKEN_<RESOURCE>` or a pipe. `--token` is the connection token there too, as in every other command. `ahpc auth X --token T` with no resource token stops and names `--resource-token`.
- A command that sends an action exits 1 with the host's reason when the host refuses it. It exited 0 once the action was sent.
- A new session is named `ahp-session:/<uuid>`, as the protocol and VS Code name one. A session another client made as `<provider>:/<id>` still opens.

### The changes screen

- `c` asks for the commit message first, says how many staged files the commit takes, and shows the host's warning in the same place. See [Changes](../subjects/CHANGES.md).
- A pull request is prepared by the host first, then opens in a form with the title, description and branches it suggested.
- Each verb has its key on its button: `c` commit, `del` discard, `s` stage, `u` unstage. A verb asks whether it is for the selected file or for every file.
- The scopes and the verbs are clicked, or reached with Tab and Enter. `]` and `x` still work.
- Each row ends with its git letter, and a staged file is marked `S`.
- The list follows the host while the screen is open: a commit empties it, and another client's tick shows.
- The commit prompt keeps every key while the list behind it changes.
- The host's answer to a verb, such as "Committed bd5f52c", is drawn as a success, with a link where the host sends one. It goes when the screen does.
- `r` ticks a file only on a scope the host keeps ticks for, and its hint shows only there.

### The screen

- The header says `ahpc`, and the new session screen shows its logo.
- A question that waits folds to one yellow line while focus is in the history. A click or leaving the history opens it again. See [Screen](../use/SCREEN.md).
- A refusal on the status row names its action and its session, and shows only on that session's page.
- The status row ends with the hints, without the screen's name.

### Connection and tokens

- When the host refuses the connection token, ahpc says so, at start and while it reconnects. A host that is down still says "Could not reach", and names the token as a cause to check. See [Connect](../start/CONNECT.md).
- A token file that cannot be read says why: missing, permission denied, or a folder. A relative `connectionTokenFile` in the config file is read from the config file's folder, and `~/` is the home folder.
- A missing token file is one line on the screen, as it is in the shell.
- A command the host refuses for a resource says `Set AHPC_TOKEN_<RESOURCE> and run it again.`
- The sign-in prompt shows a refused token only under its resource, sends once, and answers every waiting act as declined when ahpc closes.
- An action the host does not answer is reported as a refusal: "The host did not answer in 10 seconds."

### Commands

- `queue` prints the id of the queued message, so `unqueue` can take it back. `cancel` says one thing, and a cancelled `prompt` says so. See [Commands](../use/COMMANDS.md).
- `session history` prints a usage line under each agent turn: tokens, cost and context, as the host reported them.
- `session show` prints the number of open tasks when the host sends one.
- `changes <uri>` takes `--scope`, runs a verb with `--run`, and takes `--yes` and `--message` for a commit.

### The tool server

- `ahpc mcp` over stdio answers each call when it is done, in any order. A `ping` is answered at once, and `confirm_tool_call` can answer the confirmation a `send_turn` waits on. See [Tool server](../use/TOOL-SERVER.md).
- `notifications/cancelled` stops the call it names. A cancelled `send_turn` stops the turn it started, or takes back the message it queued.
- `list_automations` is served with no flag. The groups that are off are named when a client connects, and `--mcp-tools all` turns on every group.
